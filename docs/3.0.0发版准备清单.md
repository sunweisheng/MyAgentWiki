# MyAgentWiki 3.0.0 发版准备清单

本文档用于收口当前这一轮大改动，作为 `3.0.0` 正式发版前的统一检查单。

若本文档与正式发版流程冲突，以 [RELEASING.md](/Users/sunweisheng/Documents/GitHub/MyAgentWiki/RELEASING.md) 为准；若本文档与系统设计边界冲突，以 [MyAgentWiki系统详细设计.md](/Users/sunweisheng/Documents/GitHub/MyAgentWiki/docs/MyAgentWiki系统详细设计.md) 为准。

## 为什么考虑升级到 3.0.0

当前改动已经不属于普通 patch 或 minor 范围，主要原因包括：

- CLI 主入口正在从超长单文件向模块化结构拆分
- `query / answer-query / review-*` 的领域逻辑正在从 CLI 命令函数下沉到 service / repository 层
- 正式主干已经明确切到“结构优先新链路”，不再维护旧页型、旧迁移命令和旧兼容口径
- 页型、语义路由、结构账本、证据链、审核恢复链的文档口径已经整体收紧

按当前仓库版本策略，这类“阶段性重构或不兼容变更”应按 major 版本发布，因此目标版本应为 `3.0.0`。

## 当前建议

当前更适合先把这轮改动收口为一个“准备正式发版”的阶段性里程碑，再切正式版：

- 可先按 `3.0.0-rc1` 或内部发版候选状态收口
- 待完整回归、文档同步、残留清理和发版说明完成后，再正式切 `3.0.0`

不建议直接跳过收口阶段立刻发布正式版。

## 3.0.0 预期 Breaking Changes 草案

下面这些内容应按 breaking changes 口径明确写入正式 release notes：

1. 正式主干切换到当前结构优先链路，不再维护旧页型兼容层。
2. CLI 不再以旧迁移命令或旧兼容清理流程作为正式能力的一部分。
3. 页面族谱、页面路由和语义判定按当前新设计口径收口，旧概念名和旧路由假设不再承诺兼容。
4. 新工作区模板和当前 schema 以现行实现为准，历史样例工作区需要通过重跑固定流程收敛，而不是依赖兼容迁移层。
5. `query / review / ingest` 的内部模块组织已调整，若外部脚本依赖仓库内部 Python 私有函数路径，可能需要同步更新。
