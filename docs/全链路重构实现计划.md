# 全链路重构实现计划

## 1. 目标

把 `MyAgentWiki` 从“以页面生成为中心的脚本流水线”重构为 **evidence-first semantic compiler**，并按可落地阶段逐步替换当前实现，而不是一次性推翻重写。

本计划遵循三条原则：

1. 先搭基础设施，再替换高层流程。
2. 先把语义层做成可记录、可回放、可缓存的正式系统，再让更多 LLM 判定接入。
3. 每一阶段都要求 CLI、账本、测试和回退路径同时成立。

## 2. 总体阶段

### Phase 1: 语义基础设施

目标：
- 引入 `semantic/` 目录与 `state/semantic_decisions.jsonl`
- 建立 `semantic batch scheduler` 骨架
- 建立 `document_analysis / claim_candidate_quality / claim_role / page_intent` 四类任务配置
- 提供统一的 batch 执行入口与默认 hook 协议

产出：
- 工作区模板新增 `semantic` 配置与目录
- CLI 新增语义批处理入口
- `agent_hook` 新增批处理任务协议
- 初版语义决策缓存与批次报告

验收标准：
- `init` 后工作区具备语义层骨架
- `ingest` 后可单独运行语义批处理命令
- 语义决策可写入账本并可重复命中缓存

### Phase 2: document analysis pass

目标：
- 在 `normalized` 层补齐 `document_kind / structure_quality / chunk_strategy_hint`
- 让 chunking 不再只走单一路径

产出：
- `document_analysis` 决策写回
- chunking 前可读取文档结构语义
- FAQ / timeline / table-heavy / chat-log 等文档可走不同策略

验收标准：
- 语义决策能稳定回链到 normalized 文档
- chunking 可以消费文档结构提示

### Phase 3: claim candidate quality pass

目标：
- 把短句 claim 的主要筛选逻辑从固定长度阈值迁移到语义质量判定
- 为后续 `claim_role / safe_auto / review-auto` 提供统一的候选质量结论

产出：
- `claim_candidate_quality` 决策账本
- 短句灰区 claim 可批量进入语义质量判定
- `claim_can_stand_alone / safe_auto / claim_role` 可消费结构化质量信号

验收标准：
- `<12`、`claim_can_stand_alone < 16`、`safe_auto < 14` 这类主要固定长度阈值已退出主链路
- 短句灰区 claim 能稳定进入批处理、命中缓存并写回质量结论

### Phase 4: claim role pass

目标：
- 把 Claim 从“句子集合”升级成“带知识角色的 Knowledge Unit V1”
- 补齐 `knowledge_role / page_intent_hints / concept_candidate_score`

产出：
- `claim_role` 决策账本
- 查询、审核、页面候选收口可读取知识角色
- 将 `procedure / example / conclusion / structural_shell / meta` 从概念候选里分流

验收标准：
- 明显非概念内容不再自动进入概念候选主路径
- claim 角色批处理可缓存和重放

### Phase 5: page intent pass

目标：
- 把“先命名再看像不像概念页”改成“先定页型，再命名，再渲染”
- 建立正式 taxonomy：`concept / guide / example / topic / reference / timeline / overview / source-summary`

产出：
- `page_intent` 决策账本
- 页面生成链按页型路由
- `source-summary` 从杂项回收站收缩为来源入口页

验收标准：
- 章节标题、问句、总结段、示例名不会误长成概念页
- 非概念内容会稳定落到正确页型或被拒绝成页

### Phase 6: presentation rebuild

目标：
- 让 `wiki / indexes / reading_pack / answer-ready` 正式消费语义层
- 让检索、lint、review 都按 evidence/semantic/presentation 三层工作

产出：
- 检索调权从“固定旧页型”切到“intent-aware”
- 页面模板按 `page_intent` 选模板族
- lint 新增 semantic consistency 检查

验收标准：
- query 能按 `evidence / how_to / timeline / compare` 输出不同阅读路径
- lint 能检查 role/intent/page type 冲突

### Phase 7: 直接切换与收口

目标：
- 当前以结构优先新链路作为正式发布主干
- 删除旧页型、旧迁移命令和旧兼容清理流程，避免后续开发继续围绕过期机制扩展

产出：
- 当前正式工作区 schema 与初始化模板
- 结构账本、语义账本、页面路由和 lint 的收口清单
- 旧机制残留扫描清单
- 样例工作区重跑与回归测试

验收标准：
- 新工作区默认走新链路
- CLI 不再暴露旧迁移和旧兼容命令
- README、详细设计、排障文档和测试断言都不再要求旧机制存在

## 3. 代码落点

### 当前建议的模块拆分

- `src/myagentwiki/semantic.py`
  - 语义决策模型
  - batch scheduler
  - 缓存命中规则
  - ledger 读写辅助
  - semantic task contract 与决策字段校验

- `src/myagentwiki/agent_hook.py`
  - 保留现有 `review_auto / stable_promotion / grounded render`
  - 新增 batch 任务：
    - `review_document_analysis_batch`
    - `review_claim_candidate_quality_batch`
    - `review_claim_role_batch`
    - `review_page_intent_batch`
  - 默认保守模拟器应采用结构优先规则，不对中文关键词做一票判定

- `src/myagentwiki/agent_cli_hook.py`
  - 可选真实 LLM CLI hook
  - 通过 Codex 或 Claude Code CLI 接收 semantic batch payload
  - 输出统一 `{"decisions":[...]}` JSON
  - 失败、超时或无法解析时回退到保守路径

- `src/myagentwiki/cli.py`
  - `init` 负责生成 `semantic/` 骨架与配置
  - 新增 `semantic-batch` 命令
  - 后续逐步把 ingest 中的语义阶段接入这里

### 工作区侧新增内容

- `semantic/`
- `semantic/batches/`
- `state/semantic_decisions.jsonl`
- `config/project.yml` 中的：
  - `semantic.agent_cli_hook.*`
  - `semantic.batch_scheduler.*`
  - `semantic.document_analysis.*`
  - `semantic.claim_candidate_quality.*`
  - `semantic.claim_role.*`
  - `semantic.page_intent.*`

## 4. 每阶段实施顺序

### 4.1 先做的最小闭环

1. `init` 生成语义层目录与配置
2. CLI 提供 `semantic-batch --task ...`
3. batch scheduler 能对 `normalized` / `claims` 组批
4. hook 返回结构化批量结果
5. 决策写入 `state/semantic_decisions.jsonl`
6. 支持缓存命中与 dry-run

### 4.2 再做的第二闭环

1. chunking 读取 `document_analysis`
2. 短句灰区 claim 先读取 `claim_candidate_quality`
3. claim grouping / page candidate 读取 `claim_role`
4. 页面生成前读取 `page_intent`
5. lint / query 显式检查和消费这些决策

## 5. 切换策略

当前已按正式发布主干推进，不保留旧页型、旧迁移命令或旧兼容清理流程。当前代码和文档直接以新骨架为准：

- 新工作区目录结构
- 新工作区配置
- 新语义账本
- 新批处理 hook 协议
- 当前正式页型和页面路由
- 当前 schema 标记与结构账本

## 6. 测试计划

### Phase 1 必补测试

- `init` 会创建 `semantic/` 与 `state/semantic_decisions.jsonl`
- 配置模板包含 `semantic.batch_scheduler / document_analysis / claim_candidate_quality / claim_role / page_intent`
- `semantic-batch --task claim_candidate_quality` 能写入语义账本
- `semantic-batch --task claim_role` 能写入语义账本
- 相同输入重复执行能命中缓存
- `--dry-run` 不写入账本

### 后续阶段测试

- document analysis 能影响 chunk strategy
- claim role 能阻断明显错误的概念候选
- page intent 能把 `procedure / example / conclusion / structural_shell` 从 concept 路由出去
- lint 能发现 role/intent/page type 冲突

## 7. 当前实施建议

建议从 **Phase 1** 开始逐一落地，顺序固定为：

1. 语义账本与目录
2. batch scheduler
3. 默认 batch hook
4. CLI 语义命令
5. Phase 1 测试补齐

这样后面接 `document_analysis / claim_candidate_quality / claim_role / page_intent` 时，系统已经具备正式落盘、缓存、批处理和回放能力，不会再陷入“先写很多临时 if/else，之后再整体返工”的局面。

## 8. 当前进度状态

### 已完成

- `Phase 1: 语义基础设施`
  - `semantic/` 目录、`state/semantic_decisions.jsonl`、`semantic-batch`、批处理 hook、缓存与 dry-run 已落地。
- `Phase 2: document analysis pass`
  - `document_analysis` 已写回 `normalized`，chunking 已消费 `document_kind / structure_quality / chunk_strategy_hint`。
- `Phase 3: claim candidate quality pass`
  - `claim_candidate_quality` 已接入短句灰区 claim 主链路，用于替代主要的固定长度阈值判断，并为 `safe_auto` 与后续 role 判定提供结构化质量结论。
- `Phase 4: claim role pass`
  - `knowledge_role / page_intent_hints / concept_candidate_score` 已接入 claim 主链路，并开始与 `claim_candidate_quality` 结果协同。
  - `claim_role` 输入已补齐 `structure_context`，包括 section path、local headings、Evidence Block / Knowledge Unit 类型、content tags、semantic features 和证据 ID。
  - 默认 hook 已从“一票关键词”改为“强结构 / 强句式 + 负面语境 + risk flags”的保守判断。
- `Phase 5: page intent pass`
  - `concept / guide / example / topic / reference / timeline / overview / source-summary` 已进入正式页型链路。
  - `page_intent` 现已决定页型后再命名与渲染，`reference / timeline` 不再只是 query 层概念。
  - `page_intent` 已改为 claim group 级判断，payload 包含 `group_context` 和 `claim_semantics`。
  - specialized 页型增加二次验证，不足证据时降级，并将降级原因写入 page route。
- `Phase 6: presentation rebuild`
  - `query / reading_pack / answer-ready / lint` 已消费语义层，并具备 page-type-aware 的 answer shape 与 semantic consistency 检查。
  - 标题树相关的结构化层级信息也已进入 presentation 层：
    - chunk / claim source refs 已保留 `section_path_parts / section_title / parent_section_path / heading_level`
    - concept 聚合、命名和别名已消费层级信息，避免同名叶子标题被错误压平
    - query 排序、reading_pack 和 answer-ready 已显式暴露 hierarchy 命中、锚点路径、机器可读原因和中文说明
- `Codex / Claude Code LLM hook`
  - 已新增 `myagentwiki.agent_cli_hook`，支持通过 Codex 或 Claude Code CLI 执行结构优先 semantic batch。
  - 默认模板仍使用本地保守 `agent_hook`，真实 LLM hook 作为可选配置接入。
- `semantic lint brakes`
  - 已新增 `claim_semantic_risk_flags_reviewed` 与 `semantic_page_intent_brakes_reviewed` warning。
  - 已覆盖 page type / page intent / page route / claim role 的一致性巡检。
- `中文多文档类型端到端验证`
  - 已新增混合中文资料回归：流程指南、案例复盘、参数参考、时间线、学习笔记、歧义工作记录同批导入。
  - 验证 `案例库 / 产品规则 / 历史数据` 不再一票触发 `example / reference / timeline`，真正的案例、表格参考、流程、时间线仍能进入对应页型。

### 当前剩余缺口

- 补齐结构覆盖率报告和漏抽 lint。
- 决定是否新增 `duty / role` 等专门页型，以及对应目录、模板和迁移/重建策略。
- 评估是否把 `content_tags / semantic_features` 稳定写入 page frontmatter。
- 继续把 Structure IR / Evidence Block / Knowledge Unit 与 Claim、Metadata、Page Route 的边界收紧。
